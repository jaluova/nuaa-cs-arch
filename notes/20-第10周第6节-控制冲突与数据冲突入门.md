## 关键概念

### 1. 控制冲突处理机制

**基本问题**：分支指令（beq/bne）改变 PC→流水线中已取出的后续指令（误取）必须作废。

**处理三步走**：
1. **计算跳转目标**：PC+4 + immediate×4 → 新 PC 值，下个时钟 IF 段取新指令
2. **清除误取指令**：将 IF/ID 和 ID/EX 两个**流水寄存器清零**（不是清所有部件！）
3. **优化**：将分支判断从 EX 段提前到 ID 段→只损失 1 拍；再加延迟槽→可能零损失

**为什么只清流水寄存器就够了**：
- 误取指令的"破坏性"在于它携带的控制信号可能触发写寄存器/写存储器
- 清零流水寄存器 = 关闭所有后续写使能信号（RegWrite=0, MemWrite=0）
- 误取指令在 ID/EX/MEM 段"空走"但不产生任何副作用
- 清零后的指令等价于一条**全 0 空指令**（`sll $0, $0, 0`）

**清零必须同步**：清零信号（flash/clear）由 `branch_taken` 信号生成，但必须在**时钟边沿**才生效（流水寄存器是状态元件，写使能受时钟控制）。不能异步（电平有效），否则 branch_taken 变 1→立刻清零→branch_taken 又变 0→信号闪烁。

### 2. 分支执行时机分析

| 执行阶段 | 误取指令数 | 需要清的流水寄存器 | 电路改造 |
|---|---|---|---|
| EX 段（默认） | 2 条 | IF/ID + ID/EX | 无需改造 |
| ID 段（优化） | 1 条 | IF/ID | ID 段加比较器（做 rs-rt 减法） |
| **IF 段（不可行）** | 0 条 | — | IF 段只有指令字没有寄存器值；读寄存器堆会与 ID 段冲突；branch 信号需译码结果 |

**提前到 ID 段的电路改造**：在 ID 段的 register file 读出口后增加一个额外的加法器/比较器，直接从刚读出的 rs/rt 寄存器值算出 EQ → 与 branch 控制信号相与 → 生成 branch_taken。不等到 EX 段的 ALU。

### 3. 延迟槽技术

**基本思想**：分支指令之后紧跟一条**不管跳不跳都会被执行的指令**（延迟槽指令），这条指令不被清除，从而将被浪费的时钟变为有用工作。

**编译器的作用**：从分支之前的无关指令中找一条可以提前执行的，塞入延迟槽。找不到则塞 `nop`（无性能收益）。

**jal 与延迟槽**：
- 无延迟槽：`$ra = PC+4`（下一条指令地址）
- 有延迟槽：`$ra = PC+8`（跳过延迟槽指令，返回时从延迟槽后的指令继续）
- 教材表 5-172 页有详细说明

**现代 CPU 已不依赖延迟槽**：现代处理器用**动态分支预测**替代——通过分支历史表（BHT）预测跳转方向，预测错误的代价由流水线 flush 承担。

### 4. 数据冲突检测（在 ID 段完成）

当 ID 段指令的 rs/rt 编号与前面任一指令的**目标寄存器编号**相匹配且 RegWrite=1 且编号≠0→发生数据相关：

| 前指令位置 | 距当前指令 | 时间差 | 处理方式 |
|---|---|---|---|
| WB 段 | 1 个时钟 | 只差半拍 | **前半周写、后半周读**——零损失 |
| MEM 段 | 2 个时钟 | 差 1.5 拍 | **1 stall + 1 bubble**——损失 1 拍 |
| EX 段 | 3 个时钟 | 差 2.5 拍 | **2 stall + 2 bubble**——损失 2 拍 |

### 5. Stall vs Bubble 的本质区别

| 信号 | 作用对象 | 效果 |
|---|---|---|
| **Stall**（停顿） | PC 写使能、IF/ID 写使能 | 关闭→PC 不更新、IF/ID 不锁存新值→取指暂停，当前 ID 段指令**保持不动** |
| **Bubble**（气泡/清零） | ID/EX 流水寄存器清零 | 将 ID/EX 中所有控制信号+数据清零→EX 段收到一条**空指令**（全 0） |

**两者同时发生**：当 ID 段指令因数据冲突需要停顿时——
- Stall 让当前指令停在 ID 段（等前指令写回）
- Bubble 清掉 ID/EX，确保 EX 段收到的是空操作而非过期数据
- 前面已进入流水线的无关指令**正常前进**

"气泡"得名于时空图上它像流水线中漂过的一个空泡——占据一个时钟位置但不做任何有效工作。

### 6. 寄存器堆的前半周写、后半周读（最近距离冲突解决）

**原理**：寄存器堆的写操作使用**下降沿触发**（时钟周期的中间），读操作为组合逻辑（任何时候都可以读）。

- 前指令在 WB 段：下降沿写入寄存器堆（写入完成时刻 = 时钟周期的一半）
- 当前指令在 ID 段：上升沿之后立即读寄存器堆 → 此时前指令已写完 → 读到新值

**约束**：时钟周期必须足够长，使得"下降沿写入→clock-to-Q 稳定→读组合逻辑路径→下一上升沿 setup time"全部完成。

**注意**：只有寄存器堆的写口可以这样处理。PC 和其他流水寄存器必须保持上升沿触发，否则整个时序系统乱掉。

### 7. 停顿+气泡的协同操作（远距离冲突解决）

以 ID 段指令与 MEM 段指令冲突为例（差 2 拍）：

1. **检测到冲突**：ID 段硬件检测到 rs 与 MEM 段目标寄存器相同且 RegWrite=1
2. **第 1 拍**：stall 生效→PC 不更新，IF/ID 不写→当前 ID 指令保持；bubble 生效→ID/EX 清零
3. **前指令从 MEM→WB**（正常前进一步）
4. **第 2 拍**：前指令进入 WB 段→此时冲突变为"ID↔WB"情况→用前半周写后半周读解决
5. **第 3 拍**：ID 段指令读到正确新值→转发到 ID/EX→恢复正常流水
