# 第8周第6节 — 单总线 CPU 指令执行节拍分析

**日期**：2026-04-20 | **教师**：陈丹

## 本节主线

在单总线数据通路搭建完毕的基础上，逐条分析各类型 MIPS 指令的执行节拍——每一拍哪些寄存器 in/out 信号有效、数据经过哪些路径。核心结论：访存指令（lw/sw）5 拍、分支指令（beq）5 拍、运算类指令（R 型/I 型算术）3 拍。指令所需拍数的差异恰好揭示了"变长指令周期"设计的必要性。

## 关键概念

### 1. 为什么单总线需要在 ALU 旁加 X 和 Z 锁存器？

单总线结构一个时钟只能做**一次**数据传输。ALU 有两个输入端（两个操作数），但总线只有一条。因此：
- **X 锁存器**：第一个操作数先从寄存器经总线→X 暂存
- **Y 不一定是锁存器**：第二个操作数可以在下一拍直接从寄存器→总线→ALU 输入端（同时 X 的输出也连到 ALU 另一输入端）
- **Z 锁存器**：ALU 的计算结果是组合逻辑输出（不稳定），必须在时钟边沿锁存到 Z，下一拍才能经总线写回目标寄存器

### 2. lw 指令 5 拍详解

| 拍 | 数据流 | 控制信号 |
|---|---|---|
| 第 1 拍 | PC→内部总线→AR；PC+4（下地址逻辑自增） | PC-out, AR-in |
| 第 2 拍 | AR→地址总线→存储器；存储器→数据总线→DR；PC+4→Z | Read, DR-in, Z-in |
| 第 3 拍 | Z→内部总线→PC；DR→内部总线→IR | Z-out, PC-in, DR-out, IR-in |
| 第 4 拍 | `rs` 寄存器→内部总线→X；立即数（符号扩展）→内部总线→ALU 另一输入；ALU 计算结果→Z | rs-out, X-in, ALU-op, Z-in |
| 第 5 拍 | Z→内部总线→AR；AR→地址总线→存储器；存储器→数据总线→DR；DR→内部总线→`rt` 寄存器 | Z-out, AR-in, Read, DR-in, DR-out, rt-in |

### 3. R 型 add 指令只需 3 拍

| 拍 | 数据流 |
|---|---|
| 第 1 拍 | PC→AR（取指） |
| 第 2 拍 | PC+4→Z；DR→IR；`rs`→X；`rt`→ALU 另一输入（注：需要与 lw 的第 2 拍共用通路，实际操作数准备在第 3 拍也有安排） |
| 第 3 拍 | Z→PC（更新 PC）；ALU 结果（已在 Z）→`rd` |

之所以比 lw 少 2 拍，是因为不需要计算访存地址和再次访问存储器——所有操作数都在寄存器中，ALU 算完直接写回。

### 4. 为何不同指令拍数不同？

- lw/sw：需要额外 2 拍——(1) 计算访存地址，(2) 通过外部总线读写存储器（存储器比 CPU 内部慢很多）
- beq：5 拍——除了取指 3 拍外，还需计算跳转目标地址 + 判断是否跳转 + flush
- R 型：3 拍——全程 CPU 内部操作，无外部访问

**设计启示**：若强制所有指令统一为 5 拍（定长周期），则 R 型指令每执行一条浪费 2 拍——总计性能损失巨大。因此现代 CPU 普遍采用变长周期或流水线。
