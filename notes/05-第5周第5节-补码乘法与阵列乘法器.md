## 关键概念

### 1. 补码一位乘的推导逻辑（为什么不能直接拆括号）

原码一位乘的前提是"乘数为正"——此时可以把乘数拆成各位加权和，用分配律展开。但**补码表示的乘数如果为负**，这个前提不再成立：

- 补码乘数 y = -y_{n-1}·2^{n-1} + Σ y_i·2^i，其中 y_{n-1} 是符号位
- 直接拆括号会把符号位的负权当正权处理 → 结果错误
- 推导策略：先分开讨论乘数为正/负的情况 → 提取公因式 → 合并 → **凑成与源码一位乘一致的递推形式**
- 最终目标形式：每次迭代根据**相邻两位的差值** (y_{i+1} - y_i) 决定加什么

**推导要点回顾**：
1. 先把补码乘数按定义拆开（含符号位负权）
2. 对乘数为负的情况，不能直接用分配律 → 分步变形
3. 提取公因式后合并 → 凑出源码一位乘的递推公式形态
4. 最终发现规律：每次看 y_{n+1} - y_n 的差值 ∈ {-1, 0, 1}

### 2. 补码一位乘与原码一位乘的核心区别

| 维度 | 原码一位乘 | 补码一位乘 |
|---|---|---|
| 符号处理 | 符号位单独处理（异或得符号），数值位无符号乘 | 符号位必须带在一起算 |
| 寄存器宽度 | R0=n 位，R1=n 位 | R0=n 位，**R1=n+2 位**（乘数末位多添一个 0） |
| 加法操作 | 2 种状态：加 [-x]_{补} 或加 0 | **3 种状态**：加 [-x]_{补}、加 0、加 [x]_{补} |
| 判断依据 | 乘数当前位 y_i | 相邻两位差值 y_{n+1} - y_n |
| 电路 | 2 选 1 多路选择器 | **4 选 1 多路选择器**（00 和 11 连到一起） |

### 3. 三种加法状态

- 差值 = -1 → 加 [-x]_{补}
- 差值 = 0 → 加 0
- 差值 = 1 → 加 [x]_{补}

对应 4 选 1 多路选择器：00/11 两种状态连到同一路（均加 0）。

### 4. 两套乘法指令的原因

- **乘法**：有符号和无符号乘电路不同 → 所有架构都分两套乘法指令
- **加减**：用同一套可控加减电路 → Intel 不分（溢出信息存标志位）；MIPS 分 `add`/`addi`（有符号，有溢出异常）和 `addu`/`addiu`（无符号，无溢出检测）

### 5. 阵列乘法器（横向进位）的延迟分析

**基本思想**：空间换时间。用 25 个与门并发算出所有 x_i·y_j（仅 1 个门延迟），然后用加法器阵列逐行累加。

**横向进位延迟计算**（以 5×5 为例）：
- 最低位 P0：1 个与门延迟
- 第一行（5 个加法器）：进位递推公式 2n+4 → 第一个加法器和 = 6t，进位 = 5t；逐级累加至该行结束 = 14t
- 纵向传递：每向下一行，需等上位进位就位（+5t 得进位，再+3t 得和）
- **横向串行 + 纵向串行**，两个方向都慢
- 5×5 阵列最终延迟约 38t（含最后符号异或 3t）

**通用公式**：
- 第一行 n 个加法器：和延迟 = 2n+4（单位 t）
- 向下每少一个加法器，进位延迟 = 2(n-1)+5，和延迟 = 进位+3
- 斜向进位 vs 横向进位：路径不同，总延迟相近（≈37t），关键是**进位传递**拖慢速度

**为什么不能直接用先行进位优化**：因为数组是二维的，不止横向有进位依赖，纵向还有输入等待依赖——输入值要等上一行的结果就位。

### 6. 补码阵列乘法器（源码阵列 + 求补器）

补码阵列乘法器采用"笨办法"：在源码阵列乘法器的外围加**求补器**：

1. **输入预处理**：若操作数为负 → 用求补器（各位取反+末位加 1）取其绝对值的二进制表示 → 送入源码阵列
2. **源码阵列乘法**：用横向进位或斜向进位阵列完成无符号乘法
3. **输出后处理**：若结果应为负（由两个操作数符号决定） → 再经求补器转回补码表示

求补器的控制逻辑本质上就是可控加减电路（异或门 + 进位控制），通过 af/bf 信号控制是否取反。
