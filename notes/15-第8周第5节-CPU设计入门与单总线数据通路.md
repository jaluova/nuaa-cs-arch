## 关键概念

### 1. 三级时序体系

| 层次 | 定义 | 说明 |
|---|---|---|
| **时钟周期** | CPU 主频的倒数，最小时钟节拍 | 如 2GHz → 0.5ns。一个时钟信号上升沿=一次状态更新 |
| **机器周期**（CPU 周期） | 从主存取出一条指令的最短时间 | 历史上曾有，现代流水 CPU 中已无此概念。在单总线模型中一个机器周期≈取指/间址/执行中的某个阶段 |
| **指令周期** | 取指+执行一条指令的总时间 | CPI 的度量对象。不同指令 CPI 不同（lw 5 拍 vs add 3 拍） |

**定长指令周期**：所有指令统一拍数执行→简单但浪费（必须等最慢的 lw）
**变长指令周期**：按指令复杂度分配不同拍数→效率高，现代 CPU 均采用

### 2. 单总线数据通路的关键寄存器

| 寄存器 | 全称 | 功能 | 可见性 |
|---|---|---|---|
| PC | Program Counter | 存放下条指令地址，自带"+4"下地址逻辑 | 程序员可见 |
| AR | Address Register（=MAR） | 暂存访存地址，输出直连外部地址总线 | 程序员不可见 |
| DR | Data Register（=MDR） | 暂存访存数据，双端口：内连内部总线（DR-in/DR-out），外连外部数据总线（DR-E-out） | 程序员不可见 |
| IR | Instruction Register | 暂存取出的指令字，供控制器译码 | 程序员不可见 |
| X | ALU 输入锁存器 | 暂存 ALU 一个操作数 | 不可见 |
| Z | ALU 输出锁存器 | 暂存 ALU 运算结果 | 不可见 |
| GPRs | 通用寄存器堆 | 32 个 32 位寄存器，程序的数据暂存空间 | 程序员可见 |

### 3. 为何 AR 没有 AR-out 控制信号？

AR 的输出端直接连到 CPU 外部地址总线上，且这条地址总线**只有 AR 一个寄存器连上去**，不存在多个寄存器竞争总线的情况。因此不需要输出使能信号（AR-out），AR 的值"始终"驱动着地址总线。这与内部总线不同——内部总线有多个寄存器共享，需要各自的 in/out 控制信号来仲裁谁占用总线。

### 4. DR 的双端口设计

DR（MDR）连接两个方向：
- **内部总线侧**：DR-in（内部总线→DR）、DR-out（DR→内部总线）
- **外部总线侧**：DR-E-out（DR→外部数据总线）

取指令时：外部数据总线→DR→内部总线→IR
取数据时：外部数据总线→DR→内部总线→寄存器堆
存数据时：内部总线→DR→外部数据总线→存储器

### 5. 访存时序的发展

- **异步方式**：CPU 送出地址后等待 MFC（Memory Function Complete）应答信号，期间啥也不干——效率低
- **同步方式**：约定访存=固定 N 个时钟周期，CPU 可在等待期间执行其他操作——需要更复杂的控制逻辑
