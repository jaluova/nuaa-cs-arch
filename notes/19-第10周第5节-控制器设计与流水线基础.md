## 关键概念

### 1. 硬布线控制器 vs 微程序控制器

| 维度 | 硬布线 | 微程序 |
|---|---|---|
| 原理 | 组合逻辑电路直接由指令操作码+状态→控制信号 | 控制信号序列编码为"微指令"存入 ROM，按序读取 |
| 速度 | 快（纯组合逻辑） | 慢（需读控制存储器=访存） |
| 灵活性 | 差（改指令=改电路） | 好（改指令=改微程序） |
| 适用 | RISC（指令少而规整） | CISC（指令多而复杂） |
| 设计复杂度 | 高（状态爆炸） | 低（类似编程） |

**微程序的核心思想**：一条机器指令 = 一段微程序（多条微指令）。每条微指令 = 一个时钟内需要发出的所有控制信号（01 串）。控制存储器存所有微程序，指令译码后找到对应微程序的入口地址，顺序取出微指令→发出控制信号。

**为什么微程序一度很火但后来衰退**：流水线出现后，微程序的"顺序取微指令"方式与流水线的"重叠执行"理念冲突——流水线要求控制信号在每个时钟边沿即时生成，而微程序需要额外的时间去读控制存储器。

### 2. 三级时序系统的本质

在无流水线的多周期 CPU 中，每条指令的执行被划分为固定阶段：
- **取指周期**：PC→MAR→读存储器→MDR→IR；PC+4
- **间址周期**（如有间接寻址）：取操作数地址
- **执行周期**：ALU 运算 / 访存 / 分支判断
- **中断周期**（如有中断请求）：保存断点、关中断、送中断入口

每个周期再细分为若干时钟节拍（T0, T1, T2...），由一个**时序发生器**（产生 M 信号=周期选择, T 信号=节拍计数）统一管理。

**定长机器周期**：每个周期固定 4 拍→12 拍/指令（3 周期×4 拍），FSM 状态=12 个
**变长机器周期**：不同周期拍数不同→状态数更少（如前例 9 个状态），更灵活

### 3. 流水线 CPU 的基本架构

MIPS 五段流水：
```
IF ─── ID ─── EX ─── MEM ─── WB
 │       │       │        │
IF/ID   ID/EX   EX/MEM  MEM/WB   (流水寄存器)
```

**取指（IF）**：PC→IMEM→IR。同时 PC+4
**译码（ID）**：操作码→控制器。读 rs/rt→流水寄存器。立即数符号扩展
**执行（EX）**：ALU 运算（R 型）/ 地址计算（lw/sw）/ 分支判断（beq）
**访存（MEM）**：lw 读 DMEM / sw 写 DMEM。其他指令空转
**写回（WB）**：结果（ALU 输出或 DMEM 读出）写寄存器堆

**流水寄存器的作用**：每段的输出被锁存在流水寄存器中，供下一段使用。包含：
- 控制信号（RegWrite, MemWrite, ALUop 等）逐级向后转发
- 数据（ALU 结果、读出的操作数、立即数、目标寄存器编号）

### 4. 三种流水线冲突

| 冲突类型 | 原因 | 解决状态 |
|---|---|---|
| **结构冲突** | 硬件资源不足（如寄存器堆读口/写口共享） | ✅ 已解决（流水寄存器转发写寄存器编号到 WB 段同步写入） |
| **控制冲突** | 分支指令改变 PC→已取指令作废 | ⚠️ 待解决（气泡+flush+延迟槽+提前到 ID 段） |
| **数据冲突** | 前指令写寄存器/后指令读同一寄存器（RAW） | ⚠️ 待解决（停顿+气泡+重定向/旁路） |

**结构冲突的解决方案回顾**：寄存器堆只有一个写口，且与读口在同一模块。流水线中 WB 段的写和 ID 段的读可能同时发生→冲突。解决：将"要写的寄存器编号"通过流水寄存器逐级转发到 WB 段，在 WB 段的前半周期写、后半周期读（下降沿写、上升沿读），错开读写时序。
