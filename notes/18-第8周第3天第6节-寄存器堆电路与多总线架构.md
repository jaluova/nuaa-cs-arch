## 关键概念

### 1. 寄存器堆的内部电路

MIPS 寄存器堆：32 个 32 位寄存器，两个读口 + 一个写口。

**读操作（纯组合逻辑）**：
1. 5 位读寄存器编号→5-32 译码器→32 根选择线，只有 1 根为高
2. 每根选择线接对应寄存器的输出与门→选中寄存器数据上 busA/busB
3. 两个读口各有一套独立的译码器和与门阵列

**写操作（时序逻辑）**：
1. 5 位写寄存器编号→5-32 译码器→1 根选择线为高
2. 写数据 + 写使能（RegWrite）+ 时钟信号→三者经与门驱动寄存器写入
3. 课件图中缺少时钟信号连接——教师指出写操作必须在时钟边沿触发，所以与门输入端还应有时钟信号

**实验要求**：课程设计中需自己用与或非门搭建寄存器堆（不能直接调用 IP 核）。

### 2. 三总线单周期架构总结

总线越多→每拍可并行传输的数据越多→中间暂存锁存器越少→指令执行拍数越少。

到达三总线时（busA 读、busB 读、busC 写），单周期成为可能——但这只是"数据通路"层面的单周期，真正实现还需要：
- 独立的指令存储器（IMEM）和数据存储器（DMEM），否则 lw/sw 无法在一个时钟内完成取指+访存
- 所有控制信号由组合逻辑直接生成（无时序状态机）

### 3. 单周期的致命缺陷 → 流水线动机

单周期 CPU 的时钟周期由**最慢指令的关键路径**决定：

$T_{clock} \geq t_{PC\_IMEM} + t_{RegRead} + t_{ALU} + t_{DMEM} + t_{RegWrite} + t_{setup}$

对于 R 型指令，这条路径中的 $t_{DMEM}$ 完全被浪费（空转），却不得不等待。

**流水线的解决思路**：
- 在关键路径上插入**流水寄存器**（IF/ID、ID/EX、EX/MEM、MEM/WB），将长组合逻辑路径切成多个短段
- 每段时延相近→时钟周期可大幅缩短（≈ 原单周期的 1/5）
- 多条指令同时在不同段执行→虽然单条指令延迟没变（甚至因流水寄存器开销略增），但吞吐率大幅提升

### 4. MIPS 五段流水与流水寄存器

| 段 | 功能 | 段间流水寄存器 | 暂存内容 |
|---|---|---|---|
| IF | 取指令（PC→IMEM） | IF/ID | 指令字 + PC+4 |
| ID | 译码+读寄存器 | ID/EX | 控制信号 + 读出的操作数 + 立即数 + PC+4 + rs/rt/rd 编号 |
| EX | ALU 运算/地址计算 | EX/MEM | ALU 结果 + 写数据（store 用）+ 目标寄存器编号 + 控制信号 |
| MEM | 访存（仅 lw/sw） | MEM/WB | 读出的数据（lw）+ ALU 结果（其他指令）+ 目标寄存器编号 + 写使能 |
| WB | 写回寄存器堆 | — | — |

**流水寄存器在每个时钟边沿锁存上一段的输出，供下一段使用**——这是流水线能"同时跑多条指令"的基础机制。
