# 数据表示第 2 节作业：逐题提示版

这份材料只给你**解题方向、拆题顺序、关键检查点**，默认不直接把最终答案写出来。  
建议你一题一题自己先算，卡住了再回来看下一条提示。

## 第 1 题

### 题目

在 `32` 位计算机中运行一个 C 程序：

```c
float a = 0.1;
```

写出它对应的机器码（十六进制）。

### 提示版

1. 这是一道 **`float` 真值 $\to$ 机器码** 题，不是补码题。
2. 先不要管十六进制，先把 `0.1` 转成二进制小数。
3. 用“乘 `2` 取整法”试几步，你会发现它是**循环二进制小数**。
4. 因为 `float` 只有 `23` 位尾数，所以它不可能精确存下 `0.1`，只能取最近值。
5. 把它写成：

$$
1.\text{fraction} \times 2^e
$$

6. 符号位先写几？
7. `float` 的 `bias` 是多少？
8. 阶码字段等于什么？
9. 尾数字段只保留隐藏位后面的部分，保留到 `23` 位，注意舍入。
10. 最后再把 `32` 位二进制按 `4` 位一组改写成十六进制。

### 自检

- 你有没有把 `0.1` 当成有限二进制？
- 你有没有忘记 `float` 是 `1 + 8 + 23`？
- 你最后得到的应该是一个常见的教材例子，不会是特别奇怪的模式。

## 第 2 题

### 题目

1. `float a = -11.625`
2. `double b = 10.5`

分别写出机器数（十六进制）。

### 第 2(1) 题提示：`float a = -11.625`

1. 先拆成整数部分和小数部分：
   - `11`
   - `0.625`
2. 分别转二进制：
   - `11 = 1011_2`
   - `0.625` 你应该能转成有限二进制
3. 合起来后做规格化。
4. 注意这个数是负数，所以符号位不是 `0`。
5. 真指数求出来以后，加上 `127`。
6. 尾数部分去掉隐藏位 `1`，补足 `23` 位。
7. 最后转十六进制。

### 第 2(2) 题提示：`double b = 10.5`

1. 先把 `10.5` 写成二进制。
2. 做规格化。
3. 这次类型是 `double`，所以别再用 `127`，要换成 `1023`。
4. `double` 的结构是：

$$
1 + 11 + 52
$$

5. 尾数位要补足 `52` 位。
6. 最后按 `64` 位转成十六进制，所以会有 `16` 个十六进制数字。

### 自检

- 第一个数是负的，第二个数是正的。
- 这两个数都能有限地写成二进制，所以不需要处理循环截断的麻烦。

## 第 3 题

### 题目

自定义浮点格式：

- 符号位 `1` 位
- 指数位 `6` 位
- 尾数位 `9` 位

完成一系列小问。

### 这整题先统一提示

这一题不是让你背 IEEE 754，而是让你把 IEEE 754 的规则**迁移**到一个新格式。

先建立新规则：

1. 总位数是多少？
2. 指数位有 `6` 位，所以偏置值 `bias` 应该按什么公式求？
3. 规格化数的公式题目已经给你了。
4. 非规格化数的指数要和“最小规格化指数”对齐。

只要这 4 个点先理顺，后面小问都只是代入。

### 第 3(1) 题提示：求 `bias`

1. 回忆标准 IEEE 754 中：
   - `8` 位指数 $\to 127$
   - `11` 位指数 $\to 1023$
2. 它们都符合一个统一公式。
3. 现在指数位是 `6` 位，直接代这个公式即可。

### 第 3(2) 题提示：非规格化数中的 `E`

1. 非规格化数不再有隐藏位前导 `1`。
2. 但它的指数要和“最小规格化数的指数”连续衔接。
3. 所以先求规格化数里最小非全零指数对应的真指数。
4. 这个值就是非规格化数这里的固定指数。

### 第 3(3) 题提示：把 `-4.1171875` 编成该格式

1. 先看符号：负数。
2. 把 `4.1171875` 转成二进制。
3. 这个小数部分其实是有限二进制，因为它是某个 $2^n$ 分母的分数。
4. 合成二进制后做规格化。
5. 计算真指数，再转成 `6` 位指数编码。
6. 尾数只有 `9` 位，看看是否刚好够，还是需要截断。

### 第 3(4) 题提示：`(0 000000 000001000)_2`

1. 指数全 `0`，所以它不是规格化数。
2. 尾数不全 `0`，所以它是**非规格化数**，不是零。
3. 按：

$$
(-1)^{sign} \times (0.\text{fraction}) \times 2^E
$$

来算。
4. 先把 `fraction` 还原成二进制小数。
5. 再与题目给出的 `(\ \ ) \times 2^{-30}` 对照，把括号里系数整理出来。

### 第 3(5) 题提示：`(0 000100 000010000)_2`

1. 这次指数不是全 `0`，所以它是规格化数。
2. 先算指数字段的值，再减去 `bias`。
3. 有效数字要写成 `1.fraction`，别忘记隐藏位。
4. 最后整理成题目要求的 `(\ \ ) \times 2^{-27}` 形式。

### 第 3(6) 题提示：两数相加

1. 不要一上来就按机器码直接乱加。
2. 先把前两问中的两个数都还原成“真值表达式”。
3. 让它们的指数对齐。
4. 做尾数相加。
5. 再判断结果是否需要重新规格化。
6. 最后再编码回这个自定义浮点格式。

### 自检

- 你是否把“指数全 0”自动误判成了 `0`？
- 你是否在规格化数里忘了隐藏位 `1`？
- 你是否还在用 `float` 的 `127` 而不是新格式自己的 `bias`？

## 第 4 题

### 题目

已知机器数，求真值：

1. `int x : FFFF0006H`
2. `short y : DFFCH`

### 第 4(1) 题提示：`int x : FFFF0006H`

1. 这是 **32 位 `int` 补码 $\to$ 真值**。
2. 先看最高位，它是 `1` 还是 `0`？
3. 如果最高位是 `1`，说明它是负数。
4. 负数真值可以这样还原：
   - 方法一：按补码取反加一
   - 方法二：用 $2^{32}$ 减它的无符号值
5. 算出大小后，记得加负号。

### 第 4(2) 题提示：`short y : DFFCH`

1. 注意类型是 `short`，不是 `int`。
2. 所以这是 **16 位补码**。
3. 最高位为 `1`，仍然是负数。
4. 还原方法同上，但这次要按 `16` 位来做，不是 `32` 位。

### 自检

- 这题最容易错的地方是：位宽搞错。
- `FFFF0006H` 和 `DFFCH` 不能用同一套位数处理。

## 第 5 题

### 题目

已知机器数，求真值：

1. `float a : C4580000H`
2. `double b : C024800000000000H`

### 第 5(1) 题提示：`float a : C4580000H`

1. 先转成 `32` 位二进制。
2. 拆成：

$$
S \mid E \mid M
$$

3. 判断 `E`：
   - 全 `0`？
   - 全 `1`？
   - 还是普通情况？
4. 如果是普通规格化数，就用：

$$
(-1)^S \times (1.M) \times 2^{E-127}
$$

5. 尾数部分优先还原成简单二进制分数，再转十进制。

### 第 5(2) 题提示：`double b : C024800000000000H`

1. 同样先拆成：
   - `1` 位符号
   - `11` 位阶码
   - `52` 位尾数
2. 注意这里是 `double`，所以偏置值是 `1023`。
3. 先判断是不是规格化数。
4. 再还原有效数字和真指数。

### 自检

- 你是否在 `double` 题里误用了 `127`？
- 你是否在还原尾数时忘了规格化数前面有个隐藏的 `1`？

## 第 6 题

### 题目

1. `int x = -32768`
2. `short y = 522`
3. `unsigned z = 65530`

写出它们的机器数（十六进制）。

### 第 6(1) 题提示：`int x = -32768`

1. 类型是 `int`，按 `32` 位处理。
2. 这是负数，所以要写 `32` 位补码。
3. 先把 `32768` 写成二进制。
4. 再按取反加一得到 `-32768` 的补码。
5. 最后转成 `8` 个十六进制数字。

### 第 6(2) 题提示：`short y = 522`

1. 类型是 `short`，按 `16` 位处理。
2. `522` 是正数，正数补码与普通二进制一致。
3. 写成二进制后左侧补 `0` 到 `16` 位。
4. 再转成 `4` 个十六进制数字。

### 第 6(3) 题提示：`unsigned z = 65530`

1. 类型是 `unsigned`，在本题环境下一般按 `32` 位无符号整数。
2. 这是正数，不用补码负数规则。
3. 直接写普通二进制，再补到 `32` 位。
4. 最后转十六进制。

### 自检

- 第 1 小题别偷懒写成 16 位。
- 第 3 小题别把它当有符号数。

## 第 7 题

### 题目

机器使用 `6 bit` 补码表示有符号整数，`short` 用 `3 bit` 编码：

```c
short sy = -4;
unsigned short usy = sy;
int y = sy;
int x = -30;
unsigned int ux = x;
```

填写表格。

### 整题统一提示

这题是“**位串是否改变**”训练题。

你必须一行一行写清楚：

1. 原类型是什么
2. 原位宽是多少
3. 原始位串是什么
4. 赋给新类型时，位宽变没变
5. 如果扩展，补的是 `0` 还是 `1`
6. 最后按新类型解释成什么值

### 分步提示

#### 第一步：先求 `sy = -4`

1. `short` 只有 `3 bit`。
2. 先判断 `3` 位补码的表示范围。
3. 看看 `-4` 是否刚好在可表示范围内。
4. 然后写出 `-4` 的 `3` 位补码。

#### 第二步：求 `usy = sy`

1. 这里很关键：先想“赋值后保留的是值，还是位串”。
2. 在这种题里，核心训练目标通常是看**相同位串按无符号解释**会变成什么。
3. 所以先把 `sy` 的 `3` 位模式写出来，再按无符号解释。

#### 第三步：求 `y = sy`

1. `sy` 是有符号短整型，`y` 是更宽的有符号整型。
2. 位宽从 `3 bit` 扩到 `6 bit`。
3. 这时要做的是**符号扩展**。
4. 也就是看原最高位是什么，就往左补什么。

#### 第四步：求 `x = -30`

1. `int` 按 `6 bit` 补码处理。
2. 先确认 `-30` 在 `6 bit` 补码范围内能否表示。
3. 再写出其补码。

#### 第五步：求 `ux = x`

1. `ux` 是无符号 `int`，但位宽没变，还是 `6 bit`。
2. 这类题往往是**位串不变，解释方式改变**。
3. 所以把 `x` 的 `6` 位模式直接按无符号解释。

### 自检

- 这题最容易乱，是因为你边看“值”，边看“位串”。
- 一定要先写位串，再谈数值。

## 第 8 题

### 题目

写出下列表达式的二进制表示：

- `-9`
- `ux`
- `y`
- `usy`
- `(x >> 2) << 1`
- `x + y`
- `x & !y`
- `UMax`
- `TMax`
- `-TMin`

### 整题统一提示

这一题完全建立在第 7 题的结果上。  
所以你如果第 7 题没理清，第 8 题一定会乱。

先把第 7 题中这些量的**位串**全部固定下来，再做表达式。

### 各小项提示

#### `-9`

1. 按 `6 bit` 补码处理。
2. 先写 `9` 的二进制，再取反加一。

#### `ux`

1. 直接使用第 7 题你求出的 `ux` 位串。
2. 这是无符号解释，但题目要的是二进制表示，所以直接写位串即可。

#### `y`

1. 直接用第 7 题中 `y` 的 `6 bit` 位串。

#### `usy`

1. 直接用第 7 题中 `usy` 的位串。
2. 注意它的位宽应与题目对 `short` 的设定一致。

#### `(x >> 2) << 1`

1. 先做 `x >> 2`，别一起算。
2. 题目已明确：有符号数右移按**算术右移**处理。
3. 所以右移时左侧补符号位。
4. 得到中间结果后，再左移 `1` 位。
5. 左移时右侧补 `0`。

#### `x + y`

1. 用第 7 题里的 `x` 和 `y` 位串/真值。
2. 先做加法，再只保留 `6 bit` 结果。
3. 如有溢出，按机器位宽截断。

#### `x & !y`

1. 先单独求 `!y`。
2. 在 C 里，逻辑非 `!` 的结果不是“按位取反”，而是：
   - 若 `y == 0`，结果为 `1`
   - 若 `y != 0`，结果为 `0`
3. 然后把这个结果当作 `int`，写成 `6 bit` 形式。
4. 最后再与 `x` 做按位与 `&`。

#### `UMax`

1. `6 bit` 无符号数的最大值，就是全 `1`。

#### `TMax`

1. `6 bit` 补码最大值：最高位 `0`，其余全 `1`。

#### `-TMin`

1. 先写出 `TMin`。
2. 再想一个经典结论：在补码中，`-TMin` 往往会发生什么？
3. 它通常**不能被正常取反成正数**，会回到自身位模式。

### 自检

- 你有没有把 `!y` 错当成 `~y`？
- 你做右移时有没有按题目要求用算术右移？
- 你是否记得机器里表达式最终都受位宽限制？
