## 一、IEEE 754 浮点数（第三章）⭐⭐

两年均未考大题，但课堂明确标注为"必须掌握"。2024 年若考，大概率出**浮点加减法计算题**。

### 1.1 单精度/双精度格式

| | 符号位 S | 阶码 E（移码） | 尾数 M（原码，含隐藏位） |
|:---|:---:|:---:|:---|
| **单精度 (float)** | 1 位 | 8 位 (偏置 127) | 23 位 |
| **双精度 (double)** | 1 位 | 11 位 (偏置 1023) | 52 位 |

**关键公式**（单精度，规格化数）：
$$X = (-1)^S \times 1.M \times 2^{E-127}$$

- 阶码 E = 1~254（规格化数），E = 0（非规格化数/零），E = 255（无穷大/NaN）
- 隐藏位：规格化数的尾数隐含一个 `1.`，实际表示为 $1.M$
- 非规格化数：E = 0, M ≠ 0，实际表示为 $0.M \times 2^{-126}$

[笔记08]

### 1.2 IEEE 754 加减法步骤（5 步，高频考点）

**(1) 解码**：分离符号位 $S$、阶码 $E$、尾数 $M$。

**(2) 还原隐藏位**：
- 规格化数：尾数前加 `1.`（如 M = 010... → 1.010...）
- 非规格化数：尾数前加 `0.`

**(3) 对阶**：**小阶向大阶看齐**。$\Delta E = E_A - E_B$

- 若 $\Delta E > 0$：$M_B$ 右移 $\Delta E$ 位，$E_B = E_A$
- 若 $\Delta E < 0$：$M_A$ 右移 $|\Delta E|$ 位，$E_A = E_B$
- 移出位保留在 **附加位**（guard/round/sticky）中供后续舍入
- ⚠️ **不能大阶向小阶**：左移会丢弃高位 → 溢出，数值面目全非

**(4) 尾数加减**：按符号与操作决定加法/减法（用补码运算）。

**(5) 规格化 + 舍入**：
- **左规**：尾数形如 $0.0xxx$ → 左移直到 $1.xxx$，阶码相应减小
- **右规**：尾数形如 $1x.xxx$（溢出）→ 右移 1 位，阶码 +1
- **舍入到最近偶数**（默认）：guard+round+sticky 三位判断

**(6) 判溢出**：阶码是否 > 254（正上溢 → $+\infty$）或是否 < 1 且无法表示（正下溢 → 0 或非规格化数）。

### 1.3 易错点总结

| 易错点 | 说明 |
|:---|:---|
| **隐藏位还原忘记** | 规格化数尾数前有隐含 1，对阶移位时该 1 也要参与 |
| **对接方向搞反** | 永远是小阶向大阶对齐，大阶向小阶会导致不可逆精度损失 |
| **先规格化再舍入** | 规格化移动会改变 guard/round/sticky 附加位 |
| **阶码减到 0** | 先检查是否可降为非规格化数，而非直接判溢出 |
| **移码比较** | IEEE 754 阶码用移码（偏置 127），比较大小时可直接比较二进制值 |
| **舍入到最近偶数** | 中间情况（恰好一半）向偶数方向舍入 |

### 1.4 典型例题示例

计算 `float a = 1.5 + 1.5`（IEEE 754 单精度）：

- 1.5 = $1.1_2 \times 2^0$ → S=0, E=0+127=127=01111111₂, M=$1.1_2$ → 尾数取 $0.1_2$ = 100...0₂
- 机器码：`0 01111111 10000000000000000000000`
- 相加：$1.5 + 1.5 = 3.0 = 1.1_2 \times 2^1$ → S=0, E=1+127=128=10000000₂, M=100...0₂

## 二、输入输出与中断（第九章）⭐⭐

两年均未出现大题，但复习清单提醒"不要赌它不考"——2024 年试卷缺页，且中断传统上属独立大题。

### 2.1 三种 I/O 方式

| 方式 | CPU 参与度 | 数据传输率 | 适用场景 |
|:---|:---|:---|:---|
| **程序查询（轮询）** | CPU 全程查询设备状态 → 传送数据 | 低 | 低速设备、简单系统 |
| **程序中断** | CPU 启动 I/O 后继续执行，设备就绪 → 发中断请求 → CPU 响应 | 中 | 中低速设备、多任务系统 |
| **DMA（直接存储器访问）** | CPU 仅初始化，DMA 控制器接管总线完成传送 | 高 | 高速设备（磁盘、网卡） |

### 2.2 中断系统核心概念

**中断响应条件**：
1. CPU 允许中断（中断允许触发器 EINT = 1）
2. 有中断请求（INTR = 1）
3. 当前指令执行完毕（一条指令执行中间不响应中断，保证原子性）

**中断隐指令**（CPU 自动完成的硬件操作）：
1. **关中断**（EINT = 0，防止响应嵌套中断）
2. **保存断点**（PC → 栈或特定寄存器）
3. **送中断入口地址**（PC ← 中断向量）

**中断向量**：每个中断源对应一个固定的内存地址（中断服务程序入口），由中断请求信号编码后硬件自动生成。

### 2.3 单级中断 vs 多重中断

| | 单级中断 | 多重中断 |
|:---|:---|:---|
| 响应期间 | 关中断（EINT=0） | 可能在ISR中开中断 |
| 嵌套 | 不支持 | 支持（高优先级可打断低优先级） |
| 硬件需求 | 简单 | 需堆栈保存多层断点 |
| 适用 | 简单嵌入式 | 现代操作系统 |

### 2.4 中断屏蔽字（重点考点）

多个中断源按优先级排列，高优先级的中断可以打断低优先级的中断服务程序。

**设置规则**：每个中断源的屏蔽字中：
- 比自身优先级高/同级的位 = **1**（屏蔽/阻止）
- 比自身优先级低的位 = **0**（不屏蔽/允许打断）

**示例**：4 个中断源 A(最高) > B > C > D(最低)：

| 中断源 | 屏蔽字 (A B C D) | 可被打断的条件 |
|:---|:---|:---|
| A | 1 1 1 1 | 不可被打断 |
| B | 1 1 0 0 | 只能被 A 打断 |
| C | 1 1 1 0 | 可被 A、B 打断 |
| D | 1 1 1 1 | 可被 A、B、C 打断 |

> ⚠️ 教材中有的定义"1=屏蔽"（如表格所示），有的定义"1=允许"，**以课堂定义为准**。

### 2.5 CPU 开销计算（I/O 三种方式）

**典型题型**：给定设备数据传输率、中断开销、轮询开销，计算 CPU 时间占用百分比。

**(1) 程序查询**：
$$\text{CPU 时间占比} = \text{数据传输次数/秒} \times \text{每次查询时钟数} \times T_{\text{clock}}$$

**(2) 程序中断**：
$$\text{CPU 时间占比} = \text{中断次数/秒} \times \text{中断服务时钟数} \times T_{\text{clock}}$$

**(3) DMA**：
- DMA 初始化开销（少量时钟） + DMA 传送期间 CPU 被阻塞的总线周期（周期窃取）
- 因 DMA 窃取的总线周期数 = 传输数据块大小 × 每次总线窃取的周期数

### 2.6 中断响应轨迹图

CPU 在处理中断过程中，其 PC 轨迹（时间线）：
1. 执行主程序（PC 连续递增）
2. 中断请求到达 → 当前指令结束 → 关中断 → 保存断点 → PC 跳转到中断向量入口
3. 执行中断服务程序（ISR）
4. ISR 结束 → 恢复断点 → 开中断 → PC 跳回主程序

轨迹图横轴为时间，纵轴为 PC/程序位置。

## 三、寻址方式与指令格式设计（第五章）⭐

### 3.1 10 种寻址方式速查

| 寻址方式 | 操作数位置 | EA（有效地址） | 访存次数 |
|:---|:---|:---|:---:|
| **立即寻址** | 指令字中 | —（操作数 = 立即数） | 0 |
| **寄存器直接** | 寄存器中 | —（操作数 = R[reg]） | 0 |
| **存储器直接** | 内存 | EA = 地址码 | 1 |
| **寄存器间接** | 内存 | EA = R[reg] | 1 |
| **存储器间接** | 内存（二次） | EA = M[地址码] | 2 |
| **变址寻址** | 内存 | EA = R[变址寄存器] + 偏移 | 1 |
| **基址寻址** | 内存 | EA = R[基址寄存器] + 偏移 | 1 |
| **PC 相对寻址** | 内存 | EA = (PC) + 偏移 | 1 |
| **堆栈寻址** | 栈顶 | EA = SP | 0-1 |
| **复合寻址** | 内存 | EA = 基址 + 变址 + 偏移 | 1 |

### 3.2 变址 vs 基址

| | 变址寻址 | 基址寻址 |
|:---|:---|:---|
| **寄存器内容** | 数组下标（循环中递增） | 段/区首地址（不变） |
| **形式地址** | 数组首地址（不变） | 段内偏移（不变） |
| **典型用途** | 数组遍历 `A[i]` | 分段/分区访问、重定位 |

[笔记10]

### 3.3 PC 相对寻址的"加过"陷阱 ⚠️

PC 在**取指阶段已被硬件加到了下一条指令地址**（MIPS 中 PC+4）：

$$\text{EA} = \underbrace{(\text{PC}_\text{当前} + \text{指令长度})}_{\text{下一条指令地址}} + \text{偏移量}$$

- 取指阶段完成后，PC 已经是 PC+指令长度
- 因此跳转/取数基于的是"更新后的 PC"，而非"当前指令自身地址"
- 这是考试**最高频的失分点**

[笔记10, 笔记11]

### 3.4 扩展操作码设计

**核心思想**：地址码短的指令，把省出的位"借"给操作码 → 增加总指令条数。

**计算公式**（以双地址 → 单地址 → 零地址为例）：

- 初始操作码 $k$ 位，双地址指令 $m$ 条
- 可用于扩展的状态数：$2^k - m$
- 单地址最多：$(2^k - m) \times 2^a$ 条（其中 $a$ = 释放的地址字段位数）
- 零地址最多：$(\text{单地址剩余}) \times 2^a$ 条

[笔记09]

### 3.5 指令格式设计 — 逆向思维

从需求反推格式：操作种类数 → 操作码位数；寄存器数量 → 编号位数；寻址方式数 → 模式位；寻址范围 → 地址字段位数。

**编址方式陷阱**：
- 按**字节编址**：总容量 $B$ 字节 → 地址位数 = $\log_2 B$
- 按**字编址**：总容量 $B$ 字节，字长 $W$ → 地址位数 = $\log_2(B / (W/8))$
- 例：128KB 主存、16 位字长 → 按字编址 = 64K 字 → 16 位地址

[笔记11]

## 四、主存扩展（第四章）⭐

### 4.1 芯片扩展三种类型

| 扩展方式 | 问题 | 解决 |
|:---|:---|:---|
| **位扩展** | 芯片数据线不够（如芯片 1 位，需 8 位） | 多片并接，共用地址线和片选 |
| **字扩展** | 芯片容量不够（如芯片 1K，需 4K） | 多片分址，高位地址经译码器产生不同片选 |
| **字位同时扩展** | 两者都不够 | 先位后字，或先字后位 |

### 4.2 设计步骤

1. 确定芯片数量：$N = \frac{\text{目标总容量}}{\text{单芯片容量}}$
2. 确定地址线分配：
   - 片内地址线 = $\log_2(\text{芯片字数})$
   - 片选地址线 = $\text{总地址线} - \text{片内地址线}$
3. 设计片选逻辑：高位地址 → 译码器 → 各芯片 CS 引脚
4. 数据线对应连接（位扩展时同一地址选中多片）

### 4.3 典型题型

**例**：用 1K×4 位的芯片构成 4K×8 位的存储器。

- 目标：4K 字 × 8 位
- 芯片：1K 字 × 4 位
- 字扩展：4K/1K = 4 组
- 位扩展：8/4 = 2 片并行/组
- 总芯片数：4 × 2 = 8 片
- 地址线：片内 10 位（1K），片选 2 位（4 组），共 12 位

## 五、乘法与除法（第三章）⭐

两年均未单独出大题，但在 2023 Q2（有符号/无符号运算）中以概念形式涉及。

### 5.1 补码一位乘（Booth 算法）核心

**关键前提**：乘数为负时，不能直接用分配律拆开补码（符号位带负权）。

**推导策略**：提取公因式 → 凑成与源码一位乘一致的递推形式。

**递推规则**（看相邻两位 $y_{i+1} - y_i$）：

| $y_i y_{i+1}$ | 差值 | 操作 |
|:---:|:---:|:---|
| 0 0 | 0 | 部分积 + 0，右移 1 位 |
| 0 1 | +1 | 部分积 + $[x]_{\text{补}}$，右移 1 位 |
| 1 0 | -1 | 部分积 + $[-x]_{\text{补}}$，右移 1 位 |
| 1 1 | 0 | 部分积 + 0，右移 1 位 |

[笔记05]

### 5.2 不恢复余数除法

**核心理解**：将恢复余数中的"补加一次"与下一轮"左移"合并 → 用统一公式替代。

**统一公式**：
$$R_{i+1} = 2R_i + (q_i == 1 \text{ ? } -y : +y)$$

**电路关键**：$c_{out}$（进位输出）与当前商位**相同** → 直接用 $c_{out}$ 作为下一位商号。最后一次若 $c_{out}=0$ 需修正余数（加回 y）。

[笔记06, 笔记07]

### 5.3 乘法溢出判断

| 层次 | 无符号 | 有符号 |
|:---|:---|:---|
| 电路级 | n×n→2n 位，高 n 位非全 0 → 溢出 | 高 n+1 位不全 0 且不全 1 → 溢出 |
| C 语言 | `z/x == y` 逆运算验证 | 同左 |

[笔记06]

## 六、Cache 写策略与一致性（第四章）⭐

### 6.1 写命中策略

| | Write Through（写直达） | Write Back（写回） |
|:---|:---|:---|
| 写命中时 | 同时更新 Cache 和主存 | 只更新 Cache，标记 dirty |
| 优点 | 一致性简单 | 写操作快，总线流量小 |
| 缺点 | 每次写都访主存 | 替换时需写回脏块，一致性复杂 |

### 6.2 写未命中策略

| | Write Allocate（写分配） | No Write Allocate |
|:---|:---|:---|
| 行为 | 先把块调入 Cache，再写 | 直接写主存，不调入 Cache |
| 搭配 | 通常 + Write Back | 通常 + Write Through |

### 6.3 替换算法

| 算法 | 原理 | 组相联中实现 |
|:---|:---|:---|
| **LRU**（最近最少使用） | 替换最久未访问的块 | 每路维护访问时间戳/计数器 |
| **FIFO** | 替换最早进入的块 | 维护入队顺序 |
| **随机** | 随机选一路替换 | 简单，硬件成本最低 |

### 6.4 Cache 性能公式

$$\text{平均访问时间} = t_{\text{hit}} + \text{miss rate} \times t_{\text{miss penalty}}$$

$$\text{加速比} = \frac{T_{\text{无 Cache}}}{T_{\text{有 Cache}}}$$

$$\text{CPI} = \text{CPI}_{\text{ideal}} + \frac{\text{访存指令占比} \times \text{miss rate} \times \text{miss penalty}}{\text{平均每指令访存次数}}$$

## 九、流水线冲突速查

| 冲突类型 | 表现 | 解决方法 |
|:---|:---|:---|
| **结构冲突** | 硬件资源不够（IM/DM 共享、寄存器堆访问冲突） | 分离 IM/DM；前半周写/后半周读寄存器堆 |
| **数据冲突 (RAW)** | 前指令写 → 后指令读同一寄存器 | 转发(bypass) + 阻塞(stall) + 插入气泡 |
| **控制冲突** | 分支指令改变 PC → 已取的后续指令作废 | flush 流水寄存器 + 提前到 ID 判断 + 延迟槽 + 分支预测 |
| **load-use** | LW 后紧跟用同一寄存器的指令 | 转发不够快 → 必须 1 stall + 1 bubble |

## 十、流水线加速比通用公式

$$S_p = \frac{n \times k \times T_{\text{seq}}}{(k + n - 1) \times T_{\text{pipe}}}$$

其中：
- $n$ = 指令条数
- $k$ = 流水线段数
- $T_{\text{seq}}$ = 非流水单周期时钟
- $T_{\text{pipe}}$ = 流水线单段时钟

当 $n \gg k$ 时，$S_p \approx k \times \frac{T_{\text{seq}}}{T_{\text{pipe}}}$

理想情况（$T_{\text{seq}} = k \times T_{\text{pipe}}$，即完美划分）：$S_p \to k$
